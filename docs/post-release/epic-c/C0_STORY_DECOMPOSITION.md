# Epic C / C0 — C1+ story decomposition

Status: **PROPOSED**. Machine-readable list: `stories.yaml`.

Principle: each story moves one kind of ownership, has one behavior oracle
that already exists when it starts, and can be rejected without undoing
another story. Stories that need owner product decisions come after every
story that does not.

| Story                            | Moves / adds                                                                                                                                                                                                              | Why it is separate                                                                                                                                                                                    | Oracle available at start                                           | Schema change |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------- | ------------- |
| **C1** Baseline oracles          | Tests and fixtures only: golden XP awards for every CS50 item × status (including preview and final-project pairs), achievement definitions and satisfaction, link and guide lookups, label tables, V0 token/asset hashes | Every later story needs a before-state captured from the untouched baseline. Existing XP/achievement tests use synthetic data (12 and 20 cases) and visual specs only capture screenshots (G-4, G-5). | The code itself, unchanged                                          | No            |
| **C2** Programme layer + content | `src/programmes/` with guards; CS50 identity, catalogue reference, links, guide; compatibility re-exports                                                                                                                 | Resolves the Epic B deferral of CS50 links with the smallest runtime change; establishes the layer and its guards before any rule moves (G-1, G-2, G-3).                                              | C1 link/guide tables                                                | No            |
| **C3** Programme rules           | XP policy, achievement definitions, seed rule, final-project lookup into the definition; engines parameterised                                                                                                            | Highest behavior risk (XP dedupe, unlocks); isolated so the only acceptance question is "golden tables identical".                                                                                    | C1 golden tables                                                    | No            |
| **C4** Terminology and identity  | Type/category/mode labels, CS50 copy, RPG identity, map ordinal label, workflow capability                                                                                                                                | Text-only; separated from rules so text and reward risks are reviewed apart.                                                                                                                          | C1 label tables, `App.test.tsx`, RPG presentation tests             | No            |
| **C5** Scoped catalogue reads    | Active programme passed explicitly; catalogue, progress, derived media and achievement context filtered by programme                                                                                                      | Removes the crossover in probe P3 without touching storage; exercises Epic A read-boundary guards in isolation from a migration.                                                                      | P3 red test with a test-only second catalogue; Epic A access probes | No            |
| **C6** Persistence and migration | Enrolment/active state, per-programme catalogue version, explicit ownership where not derivable, backup schema upgrade path                                                                                               | Only story that changes persisted shape; needs OD-1 to OD-5 and a schema decision.                                                                                                                    | MR-0 to MR-15 fixtures and tests                                    | **Yes**       |
| **C7** Registry and switching    | Registry with fail-closed ID-collision validation; enrolment and switching                                                                                                                                                | Depends on C6 state and on a switching UX decision.                                                                                                                                                   | C5/C6 isolation tests                                               | No (uses C6)  |
| **C8** Presentation              | Badge art, emblem, optional theme tokens                                                                                                                                                                                  | Only needed when a second programme has its own visual identity; guarded by V0.                                                                                                                       | V0 oracles + owner capture comparison                               | No            |

Rejected alternatives:

- **One "extract ProgrammeDefinition" story.** It would mix persisted-value
  risk (XP source keys) with text and content moves, making a failure hard to
  attribute.
- **Migration first.** The v3 shape depends on unanswered owner decisions and
  would be designed without rule extraction or scoped reads to validate it.
- **Renaming CS50 IDs to a prefixed scheme.** It would re-key progress, XP
  sources, unlock triggers, derived media rows, routes and existing backups
  for no benefit that global uniqueness (P-3) does not already provide.
- **A deeper curriculum hierarchy.** No consumer needs it (inventory §1).
