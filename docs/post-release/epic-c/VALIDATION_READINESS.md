## 2. Evidence roles

Every later Epic C test addition declares one primary role (Lessons Learned
test-role taxonomy). The four families below must not be conflated. Family is
assigned by **product authority**, not by how the expected values were
collected: a table first generated by running current code is still a semantic
oracle if its values are externally meaningful, frozen by `SPEC.md` §4 and
owner-reviewed in C1.

| Family                          | Definition                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         | Authority                                                                                                                                      | May a later story update it?                                                                                                                                                                |
| ------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **A. Semantic oracle**          | Externally meaningful values and behaviour that Epic C freezes (`SPEC.md` §4), over reachable product states: curriculum identity and order; XP awards, preview labels and persisted reward identity; achievement definitions (IDs, titles, descriptions, categories, rule types and configurations, `xpReward`, display order) and their satisfaction; CS50 unit/item links; study-guide content; user-visible labels and copy (item/unit/asset type, item-context titles, achievement category labels and order, session-mode, RPG identity, map ordinal, rank labels and thresholds, CS50 copy) | The accepted rule or source authority (seed, definitions, link/guide modules, label tables), reviewed and frozen by the owner at C1 acceptance | **Only** by a later story whose accepted contract explicitly authorizes that product-semantic change. Recording a reason is not sufficient. An extraction story that would change one stops |
| **B. Characterization**         | Implementation-derived or internal outputs that are not externally meaningful: engine outputs for deliberately retained unreachable inputs; internal intermediate shapes not rendered or persisted; internal constants such as the definitions' `createdAt`/`updatedAt` timestamp                                                                                                                                                                                                                                                                                                                  | The baseline implementation; not independent semantic truth                                                                                    | Only by a story whose contract names the implementation change, with an owner-reviewed reason in its closure record; never to absorb a change in a family-A value                           |
| **C. Architecture / mechanism** | Ownership, dependency direction, reads/writes, stores, transactions, mutation path                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 | Accepted architecture contracts and existing guards                                                                                            | Extended deliberately with a reviewed reason; never relaxed to pass                                                                                                                         |
| **D. Visual preservation**      | Rendered appearance evidence (retained hash-bound captures + owner review) and asset/token identity                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                | Owner-accepted C1 baseline (`C0_VISUAL_PRESERVATION_PLAN.md` §4)                                                                               | Only through owner visual review                                                                                                                                                            |

Ownership does not change family. A value frozen as family A stays family A
whether it is later owned by the CS50 definition or remains shared
(`C0_PROGRAMME_DEFINITION_CONTRACT.md` §3).

[C] The original C0 described generated current-output tables as "golden"
oracles for every item × status. Only reachable states carry product
semantics; unreachable engine inputs are characterization (B). [C] The
64462f6 reconciliation classified achievement-definition snapshots, links,
guides and labels as characterization. That contradicted the `SPEC.md` §4
freeze and would have let an extraction story change frozen values by
recording a reason. They are semantic oracles (A).
