# C1 handoff — baseline characterization oracles

Status: **READY FOR OWNER REVIEW. Not started.** C1 begins only on explicit
owner authorization.

## Goal

Capture, from the unchanged accepted baseline, the behavior oracles that
C2–C8 will be judged against. C1 adds tests and fixtures only.

## Authorization boundary

C1 may:

- create a local branch from the C0 commit (or from `fd5e2d5` plus the C0
  records);
- add test files under `tests/` and fixture files under `tests/fixtures/`;
- add documentation under `docs/post-release/epic-c/`.

C1 must not:

- change any file under `src/`, `public/`, `e2e/` specs that already exist,
  `scripts/`, configuration (`eslint.config.js`, `vite.config.ts`,
  `tsconfig*`, `package*.json`, `vercel.json`) or the database schema;
- weaken, skip or rewrite any existing test or guard;
- add a dependency;
- push, merge, tag, deploy or alter any remote.

## Oracles to capture

1. **XP golden table.** For every item in the bundled CS50 seed and every
   `ProgressStatus`, the exact output of `evaluateProgressXp` (with the real
   unit, unit items, and the final-project pair states needed to trigger the
   combined milestone) and of `evaluateCompletionPreviewXp`:
   `sourceType`, `sourceId`, `xp`, `reason`, in order. Derived transaction IDs
   included.
2. **Achievements.** Serialized `achievementDefinitions` (all fields) and the
   satisfied set with trigger source IDs for a small set of staged catalogue
   states (none, week 0 complete, three problem sets submitted, final-project
   build, README+demo, course complete).
3. **Links and guides.** `getCs50UnitLink`/`getCs50ItemLink` and
   `getUnitGuide`/`getItemGuide` for every unit and item ID in the seed
   (including nulls).
4. **Labels.** Course item/unit type labels, achievement category labels and
   order, session mode labels, RPG identity labels, map node ordinal text for
   every unit, rank labels at their thresholds.
5. **V0 visual identity.** SHA-256 of every file in
   `src/features/rpg/assets/**` and `public/assets/character-profile.png`;
   the achievement → asset mapping; the custom-property names and values in
   `src/styles/tokens.css` (light and dark) and `src/styles/rpg-tokens.css`.
6. **Owner-review captures (not committed):** the surface set in
   `C0_VISUAL_PRESERVATION.md` §3, at 390×844 and 1280×900, fixed clock,
   synthetic state, stored under gitignored `artifacts/epic-c-v0-visual/`.

Oracles are generated by running the current code once, reviewed, and then
committed as fixtures; the tests compare live output to the fixtures. A
fixture that is hand-edited to make a later story pass is a failed story.

## Acceptance

- New tests pass; the full `npm test` suite passes with no skips or retries.
- `npm run lint`, `format:check`, `typecheck` and `check:circular` pass.
- `git diff --name-only <C0 commit>..HEAD` lists only `tests/**` and
  `docs/post-release/epic-c/**` (and no existing test file is modified).
- Closure record states exact counts, commands, outcomes and owner effort.

## Stop conditions

Stop and report instead of continuing if an oracle cannot be produced without
changing `src/`, if the baseline suite fails before C1's changes, or if a
fixture would contain real learner data.
