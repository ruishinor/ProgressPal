## Release identity

Version `1.3.0` is the correct semantic candidate because `v1.2.1-local-first-proof` is already an immutable ancestor and later commits add backward-compatible, user-visible RPG shell behavior. The historical `v1.2.0` and `v1.2.1` tags are not moved.

Both historical tags contain package application version `0.1.0`. That mismatch is a historical provenance defect, not a reason to rewrite tags. Backup compatibility is governed by envelope format 1 and database schema 2; historical backups whose `appVersion` is `0.1.0` remain valid.

## Candidate boundaries

This candidate preserves:

- browser-only, single-user, local-first storage;
- database schema 2 and backup envelope 1;
- current progress, XP, achievement, session, import, export, reset, and restore behavior;
- classic and current RPG routes during evaluation;
- no backend, accounts, cloud sync, analytics, AI tutor, Google/Gemini dependency, remote assets, or runtime course-data fetching.

This candidate does not claim that RPG presentation improves learning or motivation. Classic remains the control/default until the comparative task study reaches the thresholds in the remediation story.
