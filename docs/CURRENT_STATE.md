## Product facts

- Application version: `1.4.0` on the Pre-E candidate (`package.json` is authoritative; `1.3.0` on accepted `master` until the candidate is merged). It moves with application behaviour and is independent of the database.
- Database: IndexedDB `progresspal-cs50-edition`, **schema v3**. Neither value changes with the application version. **No schema v4 is authorized.** Schema v4 is proposed in `docs/post-release/epic-e/E_SCHEMA_CHANGE_DECISION_RECORD.md`, status **PENDING OWNER ACCEPTANCE**; it authorizes nothing until the owner accepts it in the repository.
- Offline cache identity moves with the package version by contract (`CACHE_VERSION` in `public/sw.js`, pinned by `tests/architecture/serviceWorker.test.ts`); its `progresspal-cache-` prefix is stable.
- Production programme registry: **`cs50x` only**, which is also the explicit default/bootstrap programme. Programvareutvikling is **not** registered and not integrated.
- Schema v3 is **not** sufficient for a faithful Programvareutvikling integration (Pre-E R4 correction of the C3/R3 statement that it was). Faithful M01/M02 needs durable learner evidence and a lesson position, which schema 3 cannot hold. The proposal is two new stores, an append-only evidence log and a mutable lesson-position bookmark, with mastery derived and never stored. It is a proposal until accepted.
- Programme content language (current owner decision, 2026-10-02): CS50x stays English. Programvareutvikling launch content stays its existing conversational, correct Bokmål; any export or runtime transformation may change representation but must not simplify, shorten, neutralise or "internationalise" the prose. Code, commands, identifiers and established technical terms stay English where authored. The platform hard-codes no single global content language: programme and content metadata carry language identity, and learner evidence and mastery do not depend on it, so a later English Programme #2 variant stays possible. This opens **no** localisation work: Epic E builds no English translation, bilingual duplication, translation tooling, locale switching, localisation UI, full i18n framework or English-specific design, and complete English M01/M02 is not a launch requirement.
- Backup baseline (current owner decision, 2026-10-02, an explicit owner-authorized preservation and compatibility change, not a silent weakening): the safe additive live IndexedDB v3 → v4 upgrade is kept, and Programme #2 with schema 4 establishes the new supported forward backup baseline. Native v4 export, import, restore and reset are required. Epic E adds **no** automatic conversion of exported schema-3 backups to v4 and no 2 → 3 → 4 exported-backup path. Existing historical conversion code and fixtures may remain. Older exported backups may be refused clearly as unsupported (schema record section 7).
- Frozen product decisions: registration is not enrolment; enrolment and switching are explicit actions in Settings → Programme; XP, level, shared achievements, study sessions, Insights, profile and weekly target are learner-global; RPG is the primary experience and Classic is secondary.
- Product boundary: learner state stays in the browser's IndexedDB and is never transmitted. The app shell and official links use the network, so the app is local-first and offline-capable once loaded, not offline-only.
