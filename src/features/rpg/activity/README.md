# Activity

The owner-supplied gold ECG heart identifies Activity in the shared HUD/profile link, Activity title and level summary. Five supplied exercise PNGs map only to their matching built-in identities; a separate supplied checkmark accompanies completed-goal text. Unsupported/custom activities use the heart fallback. Transparent PNG alpha masks use the existing theme gold; all seven files are in public/assets/activity/ and the existing service-worker static offline list. No artwork is generated or sourced externally. The earlier runner/shoe and rejected SVG approximations are superseded. Current evidence: `docs/ACTIVITY_VISUAL_REFINEMENT_HANDOFF.md`.

The page overview composes existing enabled/snapshot goal counts, participation streak and Activity Level; empty goals are explicit. Daily rows separate names, quantities and percentages, with completion text and the existing inline Log action. A text-relative container query reflows constrained enlarged text, keeping tabs and long custom names readable.

The page uses three local, keyboard-accessible sections: Today, History and Settings. Hidden panels remain mounted to retain drafts; changing sections does not write data or change the route. Goal quick entry opens inline and saves the current local calendar date through the same validated submission path as the full form. It preserves the separate full-form draft, including an explicit historical date; conflicting entry actions wait for save/cancel. Historical edits remain active until save/cancel, with a Continue editing action in History. Success feedback expires after 3.5 seconds; errors retain input and remain visible. Detailed context uses native disclosures. Phone totals stack within the same semantic table; desktop retains its columns. Current UI verification and owner review: `docs/ACTIVITY_TARGETED_UI_HANDOFF.md`; the preceding section/copy remediation is recorded in `docs/ACTIVITY_UX_HANDOFF.md`.

The RPG presentation for learner-global physical movement. The subordinate route is `/rpg/movement`; the five primary destinations are unchanged. The HUD/Profile link reads distinct keys from the date index, independently of educational HUD data. Errors do not turn a missing activity statistic into a zero or break study progression.

Validated types and relationships live in `src/lib/domain/activity.ts`; pure calculations in `src/lib/activity/model.ts`; coordinated transactions in `src/lib/db/activity.ts`. Built-in activity identities are static. Custom identities and units are stable: rename changes the display name, removal archives the definition and disables its current goals while preserving history. Repetitions, seconds and metres are stored separately as exact integers; the interface uses repetitions, minutes and kilometres. No conversion between measurement types occurs.

Each save creates an individual entry. Each date has goal context, without stored totals or level counters. Goal changes update today and future configuration; earlier snapshots remain. A date backfilled without known context has no assumed goals. Participation is one point per distinct date, level 1 plus one level per seven active dates. Entry correction/deletion recalculates it. No education ledger, XP rule, achievement, mastery or Focus-session behavior is changed.

The day input follows the current local date until explicitly selected. Saved dates never shift with timezone changes. The Activity page reads its ledger for all-time calculations and renders history in pages of 20; the persistent indicator never materializes that ledger. Optional reminders read only settings, require a visible focused tab with interaction in the last minute, stop when unmounted and discard hidden-tab time. They neither detect physical inactivity nor log movement. Default is off; rest-day planning is deferred.

Schema 5 and complete-backup integration are covered by `tests/db/activity.test.ts`. Browser journeys, language/programme switching, offline, read-only and accessibility coverage live in `e2e/activity.spec.ts`; reminder lifecycle coverage in `tests/features/rpg/activityReminder.test.tsx`. Provider rollout remains a separate owner action; see `docs/ACTIVITY_HANDOFF.md` and `infra/nhost/README.md`.
